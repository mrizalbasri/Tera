# M7.6 ML anomaly scoring implementation

Implements Part 2 of [[2026-10-05-expense-agent-backend-m76-rag-policy-ml-anomaly-spec]].
Existing processing endpoints, graph topology, Signal schema and decision precedence
remain stable. `ANOMALY_MODE=rules` is the default; `ml` selects a cached scorer.

## Modules and inputs

- `integrations/ml_anomaly/features.py`: versioned numeric features, comparable
  prior-history filtering and optional internal category context.
- `synthetic.py`: reproducible synthetic employees, amounts, timestamps and
  category histories. Separate seeds generate training, calibration and evaluation.
- `model.py`: Isolation Forest training, score calibration, version checks and
  atomic publication of a trusted local joblib bundle.
- `scorer.py`: implementation of the existing AnomalyScorer interface, neutral
  insufficient-history results and visible rule-based fallback.
- `app/train_anomaly.py`: explicit offline CLI, reload verification, benchmark
  report and optional export of synthetic feature rows.

Features are log total, log ratio against the mean of prior same-category amounts
(all comparable prior amounts when unavailable), claim count in the preceding
seven days, repeated amount share and current category's share of known historical
categories. Categories use the existing five policy categories. No employee ID,
vendor text, receipt text, answer or credential is a feature or training export.

Only claims strictly before the current claim, from the same employee/currency,
with positive finite declared amounts at most 1e15 are comparable. Fewer than
three usable prior amounts returns neutral zero. Historical category evidence
must itself have been created before the current claim; later extraction/retry
records are excluded. Historical amounts currently use declared amounts, so
claims without them do not contribute. Missing categories use the all-category
amount baseline and a fixed category share of 0.5. No domain schema migration.

## Model and calibration

Fixed random state 76, 128 trees, up to 256 samples and one training worker.
A joint Isolation Forest is supplemented by four univariate Isolation Forests
over ratio, frequency, repetition and category share. Taking the maximum of
their scores prevents an isolated strong anomaly being diluted by normal
unrelated features. This remains an unsupervised model; labels are only used
for evaluation, not fitting or calibration.

Each forest's negative `score_samples` is calibrated on separate normal data:
the 99th percentile maps to 0.7, with a fixed linear width of 0.15 and clipping
to [0, 1]. Directional marginal tails are learned from calibration features
(upper 99th percentile, lower 1st percentile for category share). Outside those
tails, marginal scores are capped just below 0.7 to handle discrete score ties.
The combined false positive rate must be measured; it is not necessarily 1%.
The score is a risk index, not a probability of fraud. Runtime review threshold
uses the existing setting and decision engine; lowering it increases reviews.

The synthetic generator includes legitimate category mix, amount variation,
routine repetition and four anomalous scenarios: spikes, bursts, repeated
amounts and category shifts. Default splits: 1,200 training normals, 400
calibration normals, and 400 normal + 400 anomalous evaluation cases. Prototype
`--verify` requires recall >=80% and false positive rate <=10% at the chosen
threshold; these are synthetic smoke criteria, not deployment acceptance criteria.

## Reliability and provenance

The content-derived detector version includes training/calibration features,
feature schema, sklearn version, parameters and calibration settings. Runtime
only reads a local artifact; it never trains, downloads or seeds data. Local
artifacts are ignored by Git. Joblib uses pickle, so the model path is operator
configuration and must point only to an artifact generated by the trusted CLI.

Absent, corrupt or incompatible models and prediction failures fall back to the
existing rule scorer with classified reasons and its actual detector version.
No raw exception text or filesystem paths enter evidence/logs. Neutral, fallback
and ML sources are visible on persisted Signals; timeline includes score, source,
reason and detector version. ML evidence contains numeric features and component
scores, not a claim that individual features causally explain the forest.

Models are cached by path/threshold until API restart. Train while the API is
stopped, then restart to adopt the published artifact. Failed synthetic verification
does not replace an existing model. Stable requests replay saved decisions/signals
without recomputing them against a newer model. High scores can escalate only;
validation, duplicate rejection and policy violations retain precedence.

## Verification

Tests cover feature leakage, unknown categories, deterministic training/inference,
concurrent reads, reload, artifact incompatibility, nonfinite predictions, fallback,
neutral histories, threshold boundaries, API escalation/replay, timeline provenance,
SQLite restart persistence, separate synthetic evaluation/export and failed training.
Routine tests need no network or model download. Full backend regression is required.
